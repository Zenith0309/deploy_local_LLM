# 9. 模型与应用评测

## 1. 为什么需要评测

换模型、提示词、Embedding、分块策略或工具实现后，系统可能在一个问题上变好、在另一类问题上退化。固定评测集可以把“感觉更好”变成可比较的证据。

## 2. 评测集组成

至少覆盖：

- 正常问题。
- 边界和空输入。
- 无答案问题。
- 多轮上下文。
- 工具参数错误。
- 权限和提示词注入。
- RAG 召回失败。
- 超时、取消和重复执行。

每条样本保存输入、期望行为、允许的答案特征、来源和版本。

## 3. 指标

| 层次 | 指标 |
| --- | --- |
| 模型 | 事实性、相关性、格式遵循 |
| RAG | 召回率、排序质量、引用准确率、拒答率 |
| Agent | 工具选择、参数正确率、任务完成率 |
| Harness | 超时、重试、越权拦截、状态正确率 |
| 服务 | P50/P95 延迟、吞吐、错误率、资源占用 |

自动评测不能替代人工抽检，尤其是事实性、安全和高风险业务。

## 4. 回归流程

```text
保存基线 → 修改模型或代码 → 运行固定评测
       → 对比质量、延迟和资源 → 通过门槛才发布
```

结果必须记录模型版本、提示词版本、工具版本、硬件和参数。
